# Task Delegation Contract Template — v0.3 / <작업명>

공통 기준: [Root Delegated Autonomy Instruction v0.3](Root_Autonomy_Instruction_v0.3.md) 및 현재 framework의 역할·gate·운영 제한.

이 문서는 Root가 기존 위임을 작업에 맞게 구체화한 기록이다. 제품 계약을 대체하지 않으며, 문서 작성이나 agent 간 합의가 사용자 승인 또는 새로운 권한을 만들지 않는다. 작업별 예외·경계만 작성하고 공통 규칙을 반복하지 않는다. 내용이 없는 항목은 공통 기준을 적용하며, 미기재를 무제한 권한으로 해석하지 않는다.

기본 작성·수렴 시점은 Workflow A의 인계 전이다. Root는 명시적 위임·제한의 최소 skeleton에서 시작해 realization과 필요한 사용자 결정을 반영한다. Realizer는 Root 권한을 승인하지 않는다. Workflow B는 인계된 기준본을 참조·소비하고 관련 근거나 범위가 바뀐 항목만 재검토한다.

간단하고 명확한 직접 B 진입은 전체 양식이 필수가 아니다. 기존 intake의 rationale·decisions·assumptions·blockers에 공통 규칙의 적용과 필요한 작업별 예외·유보·미결정만 남긴다. 기록을 생략해 새 권한이 생기거나 검증 의무가 줄어들지는 않는다.

## 1. 근거와 적용 범위

- 작업과 현재 단계: <범위>
- 인계 기준본: <기존 run/외부 인덱스 위치, brief 및 이 경계의 버전, 적용 범위. 저장 후 해시는 외부 인덱스에 기록하며 이 문서에 자기 자신의 최종 해시를 넣지 않음. A에서는 제품 계약이 아직 없어도 됨>
- 사용자 intent·명시적 합의: <원문 위치·버전>
- Realizer brief·관련 증거: <담당 반환·준비도와 저장본 연결. 외부 대화 없이 읽을 수 있는 참조>
- 현재 제품 계약·운영 제한: <존재하는 문서와 정책 참조. 아직 없으면 그 상태를 명시>

## 2. 반드시 유지할 결과

<목적, 입력·출력 의미, 핵심 사용조건, 품질·실패 처리 등 이 작업에서 이탈 시 문제가 큰 조건만 원문 참조와 함께 작성한다. 정의나 수치를 새로 만들거나 제품 계약과 별도로 관리하지 않는다.>

- <보존조건 — 근거>

## 3. Root가 선택할 수 있는 범위

<공통 지침을 넘어 추가로 설명할 필요가 있는 재량만 적는다. 대안을 선택해도 유지해야 할 품질·자원·영향의 경계를 근거와 함께 밝힌다.>

- <재량 영역 — 허용 경계 — 기존 위임의 근거>

brief·제품 계약의 의미 변경과 준비도는 각각 Realizer·Contractor가, 검증 판정은 Verifier가 책임진다. Root의 해결안 채택 권한과 이 역할들의 작성·판정 권한을 혼동하지 않는다.

## 4. 사용자 결정으로 남겨둘 범위

<기존 근거·위임으로 정당화되지 않는 중요한 의미·우선순위·손실·범위·외부 권한만 적는다. 이런 사안이 아직 발견되지 않았으면 그 사실을 적되, 향후의 모든 선택을 포괄 승인한 것으로 보지 않는다.>

- <유보 결정 — 사용자 선택에 따라 달라지는 결과>

## 5. 현재 미결정과 진행 가능 범위

- <미결정 사항 — Root 조사로 해결할 내용 또는 사용자에게 필요한 내용 — 확정 보류할 부분 — 계속할 수 있는 독립 작업>

미결정 항목을 가정으로 조사·실험할 수는 있으나, 근거·권한 확인 없이 제품 계약·구현의 확정 의미로 채택하지 않는다.

## 6. 재검토 조건과 전달

- 이 위임 판단을 다시 확인할 조건: <관련 intent·사용범위·기술 가정·누적 영향의 변화 등 작업별 항목>
- 적용할 작업 예산·공식 repair 제한: <현재 정책 참조. 이 문서에서 새 한도나 연장 권한을 만들지 않는다.>
- 중요한 자율 결정과 Delta Check의 기록 위치: <기존 기록 참조>
- 사용자에게 드러낼 중요한 결과 차이·한계: <진행·최종 보고에 반영할 내용. 사용자 승인이 필요한 항목은 보고만으로 대체하지 않는다.>

새로운 권한을 요청하는 내용이 포함되면 해당 항목을 기존 위임과 분리한다. 그 항목은 명시적 승인 전까지 적용하지 않는다.
